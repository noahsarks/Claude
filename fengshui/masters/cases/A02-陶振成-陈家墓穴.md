# A02 · 陶振成为陈家选墓穴

| | |
|---|---|
| 术者 | 陶振成 |
| 时间 | 2016-09 至 10（研究者观察的是**第二次**到场） |
| 地点 | 溪头村，距金华市约 70 km，位于市辖区边缘 |
| 坐标 | 未知 |
| 证据等级 | **A** —— 研究者在场观察 |
| 出处 | Ren PhD thesis, Ch.5；陈家访谈 2016-09；陶振成访谈 2016-09-15 |

## 事由

陈家长者新丧。村里已全面执行公墓制度（1997《殡葬管理条例》禁止野葬），
但仍认为必须请人看。经邻居推荐请陶振成。

## 关键前提：坐向在到场之前就定了

> 「第一次，陶已经**通过分析死者的生辰**算出了首选朝向。」

三个候选穴位都在公墓**同一排**，**同一朝向**，各 **1.3 m × 1.3 m**，
差别只在**面对的景观不同**。

也就是说：本案中「坐向」不是地形的函数，是**死者生日的函数**，且先于踏勘确定。

## 术者当场做了什么

1. 调整自身相对于罗盘、墓穴、前方山峦的位置。
2. 站在墓前、与墓同向，读罗盘以评估朝向与最佳下葬时辰；反复微调数次求精确读数。
3. 向家属确认：九天后的下葬时辰合适。
4. **逐一读三个候选穴的周边环境**，判据是：

   > **「前方山的层数越多，风水越好。」** 陶向家属解释：**山有几层，代表气的强弱。**

5. 选定最靠公墓东侧的一穴，**因为它面对五层山**。
6. 陶与陈家还特别欣赏穴前的小山丘与其后的群山——
   **合起来形如一只元宝，且被一条河环绕**。陶断此风水主财富。
7. 家属满意。长子说：「这里景色好，父亲一定高兴。」

## 判据拆解

| 项 | 内容 |
|---|---|
| **terrain** | ① **前方山层数 = 5**（唯一被计数的地形量）② 穴前小丘 + 其后群山**合成元宝形** ③ 河流环绕 |
| **liqi** | 坐向（由生辰推定，先于踏勘）、下葬时辰（罗盘 + 择日） |
| **social** | 公墓制度约束（三穴只能在同一排、同朝向）、家属集体在场认可 |
| **rule_invoked** | 「前方山层数越多风水越好，层数代表气的强弱」；元宝形主财 |
| **judgment** | 取东侧穴（五层山） |
| **outcome_claimed** | 无（事件时点即结论时点） |

## `decision_driver`

**前方山的层数。**

这是整个田野材料里**唯一一个被术者明确计数、并直接决定选择的地形量**。
三穴同向、同大小、同排，把理气、坐向、择日全部固定住了，
使得这一案成为罕见的**地形单变量对照**：变的只有视野。

「元宝形」是事后的整体审美确认，不是筛选依据（三穴都在同一排，看到的大体是同一片山）。

## 对本项目的意义

| 字段 | 值 |
|---|---|
| `testable_by_us` | **部分可以** —— 若能拿到坐标，「前方山层数」是可以从 DEM 直接算的 |
| `maps_to_component` | **我们的引擎里没有这一项。** 现有 `xuanwu / hulong / xiangbei / mingtang / water / water_gate / zangfeng` 七个分量都没有「视线方向上穿越山脊的次数」 |
| **待办（已在 rules v0.11 记录）** | 新增 `ridge_layers` 指标：沿朝向 ±θ 的剖面上，统计高程剖面穿越局部极大值（山脊线）的次数。这是本目录对引擎最直接的一条输入 |
| **反向启示** | 坐向来自生辰，不来自地形。我们的引擎目前**从地形反推最优朝向**，这与实践相反。坐向应改为必填输入 |
