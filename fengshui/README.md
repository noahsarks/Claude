# 峦头评分引擎 · M0 原典抽取与初步验证

从形势派（峦头）原典抽出可计算规则，用 Copernicus DEM GLO-30（30 m）对给定经纬度评分，
并用历史选址点做初步验证。

**这是 M0 阶段产物，不是可用产品。** 五个验证点里只有明十三陵长陵能说通过，见下方结果。

## 规则从哪来

规则全部抽自 [youngzs/xuanxue](https://github.com/youngzs/xuanxue) 仓库 `docs/` 下的原典正文，
`rules_luantou.yaml` 中每条都带 `source` 字段可回溯：

| 原典 | 篇目 |
|---|---|
| 葬经 | 气感篇、因势篇 |
| 葬经翼 | 原势、察形、穴病、四兽砂水、明堂、水口 |
| 博山篇 | 论龙、论砂、论水、论明堂、论平地 |
| 雪心赋 | 第四章 论水法 |
| 发微论 | 聚散篇、向背篇、顺逆篇 |

共 9 条吉格 + 7 条凶格。另有 7 项**读到但本版算不了**的内容，登记在 `not_implemented`
（窝钳乳突四穴形、小明堂、五星九星山体形态、龙的剥换过峡、完整罗城水口、水的色味气、
以及全部理气内容）——没有假装实现。

### 权重的原典依据

不是拍脑袋。《葬经》「风水之法，得水为上，藏风次之」给出显式序关系；
《博山篇》「其中最重惟中明堂」「四砂惟朝，关系匪轻」。
这几条定下权重的大小次序，序内数值仍是估值，待外部专家排序校准。

### 双尺度

《葬经·因势篇》「千尺为势，百尺为形，势来形止」——靠山、朝山按**势**算（0.3–6 km），
明堂、龙虎、割脚按**形**算（0.1–2 km）。
起因是实测发现长陵的靠山天寿山在 3.7 km 外，原定 3 km 分析半径整个漏掉了它。

### 凶格是乘性折减

《葬经翼·穴病》「如是者，法不可葬」——一个致命病要能废掉整个穴，
所以七条凶格实现为 `Π(1−pⱼ)` 折减系数，不是减分项。

## 用法

```bash
pip install -r requirements.txt
bash scripts/fetch_dem.sh ./dem          # 下载 9 幅瓦片，约 420 MB
```

```python
import luantou as L
reg = L.Region("长陵", 40.2967, 116.2331)      # 建镶嵌 + 汇流网络，约 20 s
M = L.metrics(reg, 40.2967, 116.2331)          # 原始指标，约 0.22 s
# 坐向可指定：L.metrics(reg, lat, lon, theta_deg=0.0)   theta_back = 指向靠山的方位
S = L.score(M)                                  # {components, mode, base, faults, final}
```

`luantou.py` 里 `DEM_DIR` 默认指向 `/home/user/fs/dem`，按实际路径改。

## 验证结果

百分位 = 目标点得分高于百分之多少的**匹配对照点**
（同区域 5–25 km 内、高程差 ≤150 m、3 km 起伏度 0.6–1.7 倍）。

| 点位 | 第一轮 | 第二轮 | 最严口径 |
|---|---|---|---|
| 明十三陵·长陵 | 99.4% | 98.9% | **86.0%** |
| 北京故宫·太和殿 | 91.7% | 72.8% | 44.7% |
| 清东陵·孝陵 | 4.4% | 57.2% | 40.7% |
| 秦始皇陵·封土 | 76.1% | 59.4% | 15.3% |
| 唐乾陵·北峰玄宫 | 0.0% | 0.0% | 0.0% |

- 第一轮：初始规则 + 未核准的坐标，自动坐向
- 第二轮：修正坐标 + 修正三处规则实现错误，自动坐向
- 第三轮（最严）：**刻意不公平的下界**——目标点钉死在史载坐向，
  对照点可在 8 个方位取最高分。真实水平在第二轮与第三轮之间。

**只有长陵稳过。** 这一轮只够说规则抓到了东西，不够说模型成立。

### 判别力（长陵 vs 180 个匹配对照的分项均值差）

```
水口关锁  +0.43
龙虎      +0.28
向背开面  +0.24
得水      +0.21
玄武      +0.16
藏风      +0.07
明堂      +0.06
```

判别力第一和第三的两条（水口关锁、向背开面）来自原典，
是凭「风水常识」写不出来的；而常识性的藏风、明堂在同一片山里几乎不区分。

### 混淆变量实测

随机背景对照 vs 匹配对照的百分位差：孝陵 +17.2、秦陵 +17.8、故宫 +2.2、长陵 +1.1。
**山地陵墓虚高 17 个百分点。**按随机背景点报结果，孝陵和秦陵都会被写成「验证通过」。
匹配对照抽样不是可选项。

## 已知问题

1. **坐山方向自动检测不可靠**，是全链路最弱一环。高程质心法在盆地里指偏
   （孝陵指到 325°，实为正北）；「上升最连贯方位」法在长陵指到侧脊（正东）。
   θ 偏 45° 影响总分 0.05–0.09，足以跨一个等级。**坐向应当作为输入，不是推断。**
2. **缺骑龙穴分支。**乾陵因山为陵，玄宫在梁山北峰顶，按平地起穴规则必然垫底。
   《葬经翼·察形》「非腰结必骑龙」，骑龙穴另有「倒、顺、横、侧」四势判法，未实现。
3. **水系由 DEM 汇流推导**，非真实水文数据。平原大河与湖泊会失准，
   秦陵这类近渭河的点水法欠准。应接 HydroRIVERS + OSM 替换。
4. **验证点坐标需逐点核准。**本轮五个点我给错两个（孝陵偏 1.55 km，
   乾陵偏 160 m 且低 84 m），均已修正，但说明坐标必须核到宝顶/主殿几何中心。
5. **无负样本。**目前只有正样本与随机/匹配对照。
6. `scripts/revalidate.py` 从 `validate.py` import 工具函数，会连带触发一次完整重跑。
   脚本按原样保留（即产出上述数字的版本），未做重构以保证可复现。

## 第二轮：大样本检验（4356 处国保单位）

正样本来自 Wikidata 全国重点文物保护单位（4356 处带坐标，CC0），按名称分陵墓类／建筑类。
三个研究区各撒 3000 随机背景点，共 9817 次单点分析。

### 结果：没有稳定信号

| 研究区 | 类别 | n | AUC 原始 | AUC 匹配 | 增益 匹配 | MW p |
|---|---|---|---|---|---|---|
| 京津冀 | 陵墓 | 8 | 0.751 | 0.564 | +0.200 | 0.012 |
| 京津冀 | 建筑 | 74 | 0.427 | 0.518 | −0.138 | 0.032 |
| 晋南豫北 | 陵墓 | 37 | 0.568 | 0.473 | −0.233 | 0.154 |
| 晋南豫北 | 建筑 | 187 | 0.617 | 0.560 | +0.186 | 8.5e−08 |
| 关中 | 陵墓 | 27 | 0.380 | 0.281 | −4.400 | 0.032 |
| 关中 | 建筑 | 34 | 0.463 | 0.457 | −1.200 | 0.457 |

**但这不是规则失效的证据**，见下。

### 为什么测不出：信噪比 1:1

- 正样本与背景的分数差（全部信号）：**+0.043**
- 位移 1 km 造成的分数扰动（中位）：**0.042**
- 背景分数标准差：0.120

Wikidata 坐标与人工核准点的中位偏差为 **1.3 km**（主因是"整体 vs 局部"，如"明十三陵"点为陵区质心）。

### 衰减与样本量（`scripts/sensi2.py`）

| 坐标误差 | 相关 r | 可测效应 | 每组所需 n |
|---|---|---|---|
| 0 | 1.000 | 0.0430 | 122 |
| 250 m | 0.773 | 0.0333 | 204 |
| 500 m | 0.585 | 0.0252 | 357 |
| 1 km | 0.549 | 0.0236 | 405 |
| 4 km | 0.432 | 0.0186 | 654 |

本轮陵墓类合计 72 点 @ ~1.3 km 误差，需要 405 点，**欠 5.6 倍**。
建筑类 295 点接近门槛，这解释了为何唯一强显著结果出在建筑类。

### 上限测试：坐标不是唯一瓶颈（`scripts/ceiling.py`）

五个人工核准点各在 ±100 m 内抖动 50 次，**平均 SD = 0.024，占 0.043 效应的 57%**。
病根是指标的高频敏感性：`h0` 取单像元、TPI 与粗糙度用小邻域、后方剖面只沿单一方位线采样。

### 修订后的优先级

1. **指标空间平滑**（纯代码）：`h0` 用 3×3 邻域中位数；剖面取 ±10° 三线平均；TPI 前先轻度低通。预期把抖动 SD 压到 0.008 量级 ≈ 有效样本量放大 9 倍。
2. 平滑后重测位移敏感性，重算精度门槛与样本量。
3. 补骑龙穴分支（关中陵墓 AUC 0.281、p=0.032，与因山为陵一致）。
4. 最后才建 200 点精验证集。

### 另外确认的两点

- **分层匹配一律把 AUC 拉向 0.5**，六个类别无一例外——原始背景对照双向污染结果，匹配对照不是可选项。
- Wikidata 坐标**不是**系统性 GCJ-02：做 GCJ→WGS 转换后中位偏差反而从 1326 m 变成 1071 m 且方向不一致（`scripts/coordcheck.py`）。
